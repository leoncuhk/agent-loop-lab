# 四方法实现审查与改进记录

2026-11-07。使用Matt code-review的Standards/Spec两轴，以及codebase-design的三种Interface设计。固定基准为`reviews/fair-v2-baseline`的字节快照；此独立实验没有Git工作流，不另建外部tracker。

## Standards

独立复查发现2项P2，均离线复现后修复：

1. **完整性停止绕过批次收尾。** 旧run_study在源码改变或future异常时直接抛出，已有记录保留，但manifest无finished_at、stop_reason和not_run。改为研究级finally统一收尾；第二block指纹变化的负样本先失败后通过。原始trial/attempt不覆盖。
2. **报价来源未完整进入quote身份。** 旧goal_key遗漏case.funds，同revision更新posted_credit后重评同SKU会覆盖旧ID金额。现以完整source_digest构造goal_key与quote_id，旧记录保留，提交时判来源失效；新报价ID需模型实际观察后才可提交。

没有将Fowler代码气味启发当作必改标准；自动格式问题由ruff处理。

## Spec

独立复查发现2项P2：

1. 与Standards相同的quote不可变性问题，已按上述完整来源身份修复。
2. **报告未实现协议约定的全部指标。** 旧版本只汇总完成项。现主率分母为预分配trial，另外记录未运行、首次/恢复交付与通过、可行/最优、分开输入输出与unknown用量、逐题数据和任务聚类配对bootstrap。明确说明有限任务、未校正多重比较、全通过零区间不等于普遍等效。

首轮独立审查支持的边界：公共World不保存gold/未来消息；quote不枚举全空间；eager/skills同正文；worker持久且共享预算；技术恢复保留首次attempt；最新需求与实际审计事件ID独立核验。

## 方法实现改进

- 公共assess/quote/stage接口由所有方法共享，确定性金额与实体关联从模型文本拼装中移出；不新增只给某一组的能力。
- tools只获共同目标和工具契约；eager与skills共享同一正文，仅加载方式不同；multi可以选择不用worker，主结果仍按分配方法统计，另报实际拓扑。
- multi按完整平台解空间或账务分支委派；worker跨revision复用，partial返回已登记成果，主循环留3次收尾额度。
- 一次调用结束前落盘start记录，结束后保存finish；未知用量保留。一项传输超时只消耗该trial的统一恢复额度，额度/认证类系统故障则结束当前块后停止新块。
- 由于CLI无法证明token硬上限，资源比较明确为同请求次数/effort/超时机会；实际tokens与未知值另外报告。

## 工程验证与开发阶段

截至修复后，48个公开边界测试和ruff检查通过。测试包括数百个开发候选的独立报价算术交叉核验、资金更新不可变引用、未来消息/gold哨兵、相同知识正文/工具schema、持久worker、partial与收尾额度、超时恢复/业务失败不重试、配对覆盖和完整性停止。

账号额度拒绝的`fair-dev-v1`没有有效模型答案，已显式失效，不占方法调优成绩。账号切换后`fair-dev-v2`完整12/12通过；四组各3/3。此轮固定资料没有触发后来查明的资金更新缺陷；原记录保留。

因为修复后代码版本变化，使用同一已见开发面板再跑`fair-dev-v3`，四方法获得相同机会。不得将dev成绩当作新题泛化结果。只有该批完整且源码匹配后才允许freeze、再解封独立新题。

两轴各2项，最高均为P2；重复的quote问题分别记录，不合并为方法效果结论。最终认知依赖冻结后的实测，不依赖工程测试数量。
