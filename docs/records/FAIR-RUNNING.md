# 冻结后的公平对照

日期：2026-11-07。有效开发阶段已完成两轮，每轮四组各3题、每题1次。`fair-dev-v2`、`fair-dev-v3`均为12/12完整通过。四组获得相同面板和修改机会，第二轮为共享接口/实验收尾修复后的同面板回归，没有根据留出成绩调参。

正式版本已通过独立Standards/Spec复核，无阻断级发现。冻结记录：`reviews/fair-v2-freeze.json`。正式运行目录：`runs/fair-holdout-v2`。

## 主对照范围

- 12个独立准备的新实例：6个组合采购、3个多轮修改、3个账务审计；含3/4/5类采购与3/4分支审计。
- 四种预先声明的配置：tools、eager、skills、multi；每题每方法2次，共96trial。
- 所有组同一模型gpt-6.1-sol、low；24次模型请求额度，主子与最多一次技术恢复共用。240秒请求超时，最多4个并行模型请求。
- 相同业务规则、公开数据与报价/审计/提交工具。报价只算模型提出的候选，不调用评分oracle；审计工具只合计模型选中的事件ID。
- eager/skills同正文，加载时机不同。multi可自适应不委派，记录实际worker调用，未委派的通过不能支持独立上下文收益。
- 不根据最终成绩再修改提示词、预算、任务或评分。发现装置问题保留原结果，另记录效度与修复，不悄悄重跑失败。

## 重要解释边界

当前测试的是**同资源上限和同等开发机会下的完整应用配置**，不是所有可能实现中的最优点，也不是单一“Agent数量”的因果效应。公共quote改进已经把一部分数字绑定工作交给确定性程序，模型仍负责目标理解、候选覆盖与选择、事件版本判断。

小/大方法库按封存顺序交替分配，同一case四方法一致。它支持给定库规模下的方法比较；不同case的小库/大库均值不能单独证明规模效应。

同一block四方法同时运行，共享并发限制，耗时包括CLI与排队；输入tokens包括模型运行基础上下文与历史回放。没有逐请求美元计费依据，因此金额未知。CI按任务聚类，重复不是独立新任务；合成样本和单模型不能外推为真实业务可靠性。

## 记录与停止条件

首个attempt记录始终保留，只有传输超时允许一次同策略技术恢复；业务错误、次优、任务额度耗尽不会自动重试。模型服务额度/认证系统错误停止后续block，留下未运行清单；所有分配trial与完整配对覆盖共同决定是否可比较。

运行入口：

```bash
uv run --frozen python -m loop_lab.fair.study report --output runs/fair-holdout-v2
```

这条命令只重算已保留记录，不调用模型。运行未结束时报告将标明配对不完整。
