# 把「怎样拆 Agent」变成一个可测的问题

[Anthropic 原文](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)针对的是一个实际取舍：按业务部门配置专家很自然，但同一条用户请求可能同时依赖几个部门。把流程写成独立文档，和把工作交给另一个决策者，是两个不同的选择。文章既建议考虑折回路由、计划与领域决策，也讨论并行工作、独立验证与权限隔离。[原版迁移 kit](https://github.com/anthropics/single-agent-loop-kit)是检验建议的起点。本仓没有覆盖原文所有迁移方式，也没有复现作者的企业部署。

| 名称 | 在本仓具体是什么意思 | 谁做下一步决定 |
|---|---|---|
| 工具 Tool | 一个有名称、说明、参数和返回的接口：查订单、获取签收日期、给候选报价、提交已获准的动作。说明帮助模型选择；资格、版本与幂等检查要由代码执行。 | 调用方模型接收结果；工具也可在代码中拒绝动作。 |
| 手册 Skill | 单独维护的政策解释或程序性知识，可先提供索引，再经 load_skill 取正文；全量加载则是一开始就提供相同正文。 | 仍是同一模型在同一主循环中决定。 |
| 子 Agent | 持有自己上下文、提示、工具范围与预算的执行者。协调者传任务，子 Agent 决定如何行动，再回传结果。 | 中间多了一位决策者。主 Agent 仍负责整件事是否办完。 |

工具说明当然也是上下文；“无 Skill”绝不等于“无上下文、无业务数据”。能否发现某个工具与是否有权执行也不同。工具可取回一篇手册，手册也可指导使用工具。关键是**事实、流程和执行权限分别由谁维护，决策时实际看见了什么**。在 [SQL 附项](../fieldwork/2026-11-08/langchain-reference/README.md)中把资料从 Skill 换成返回相同正文的普通查询工具，结果没有变；在 [aidless](../fieldwork/2026-11-08/aidless/README.md) 中，无论怎样描述权限，真实后端写了几次仍须看写入回执。

## 一次任务，四处可能出错

~~~mermaid
flowchart LR
    U["用户：若新设备晚于周五才退旧单"] --> Q["查询：哪天到、哪笔单"]
    Q --> D["决策者：核对原条件与实测日期"]
    D -->|条件不成立| N["不写，解释依据"]
    D -->|条件成立| W["业务工具：核权限、当前版本与唯一写入"]
    W --> R["回执：已办哪笔单"]
    R --> F["用户：收到结果与必要依据"]
~~~

查两件事即可看出架构是否帮忙。第一，在决策者**发起写入之前**，同一任务中是否已有带实体和时间的原始证据？读和写在同一批盲发，即使后端先执行读，也不算模型看见了结果。第二，已有证据是否反映在后台动作和用户收到的答复里？日语电商 A1 两次都把签收日回传给协调者，但最终只报截止日；官方 t11 旧路由已写入，却未返回单号。不能用“曾调用物流”或“开单成功”代替端到端验收。[两项轨迹的对照](../fieldwork/2026-11-08/README.md)

## 选择下一次实验，而不是先决定赢家

| 观察到什么 | 值得放在同题上比较的方案 | 应提前写下的验收 |
|---|---|---|
| 已知事实和短流程足以决定一个动作 | 工具单循环；同一循环再加手册 | 业务成功、误写、缺回执和总请求数。各组看到相同业务事实。 |
| 有专门规则，但只有少量任务用到 | 全量同样正文、按需同样正文、普通查询取同一份资料 | 分别测发现、加载、实际使用、最终结果和 tokens；加无关手册或相冲突版本，检查选错率。 |
| 各专家反复查同一个订单 | 保留现状、给原专家补必要取数或证据、把最终决定折回来 | 逐次查重复查询、条件传达、最终说明、P95 时间与总资源。不要只移除专家组的权限制造弱基线。 |
| 几条线索可独立调查，或必须隔离审查者 | 单循环调查／工具过滤，对照独立并行调查或独立核验 | 固定总资源，测有来源的新增发现、去重覆盖、检错召回与误报、端到端时间。预算应含所有子调用。 |
| 操作可能产生真实副作用 | 相同 Agent，改工具的事务和批准契约 | 注入旧草案、身份错配、重复提交、超时与拒绝。对数据库与回执逐笔核对。 |

**可复用的预登记（复制填写）：** 用户任务＝___；必须依据的事实及其权威来源＝___；只改变的架构因素＝___；保持不变的模型／知识／权限／预算＝___；对照组的开发机会＝___；正例／只翻转一个条件的反例／邻近不受影响的任务＝___；主指标及最小有意义的改善＝___；保护指标（误写、漏项、超时等）＝___；运行顺序、独立样本单位、重复数、停止和缺失处理＝___；谁用什么独立证据验收＝___；出现何种结果就保留旧方案＝___。冻结后另取新题，不把失败回归题再称为留出题。

**我们愿意被什么证据说服？** 若在新的高耦合任务上，补交接后既不丢信息、又保持相同资源，折回就不是必要条件。若分支调查在同预算同权限下有更多经核实的新发现，或独立核验在相同误报率下检出更多真实错误，就有理由保留子 Agent。本仓已经给出前一种可能性的短任务例子；后一类正收益仍缺直接证据。
