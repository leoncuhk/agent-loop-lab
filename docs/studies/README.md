# 哪些证据支持我们的选型判断？

**需要把刚查到的事实用于下一步动作时，先用一个主 Agent。** 现有证据最清楚地支持减少交接和调用，并不支持“一定更准确”。下面按要判断的问题列证据。一次运行、一道独立题、一次模型调用是三个不同单位。

| 要判断什么 | 可以引用的结果 | 为什么这个比较有用、边界在哪 |
|---|---|---|
| 折回主循环能省什么？ | 直接执行与两种专家交接都 6/6；直接执行共 16 次模型调用，专家方案各 25 次。[kit 协议](../../fieldwork/2026-11-08/kit/PREREG.md) · [逐组结果](../../fieldwork/2026-11-08/kit/README.md) | 固定模型、工具和业务后端，只移动执行责任或改变交接内容。两类条件任务、四种后台状态；没有测长时间并行调查。 |
| 不加额外手册或子 Agent 也能办对吗？ | 12 道冻结新题、每题两遍。工具、全量手册、按需手册、可委派组各 24/24，无重试；工具组平均 tokens 最少。多 Agent 组仅 6/24 次实际委派。[规格](../../FAIR-SPEC.md) · [结果](../../FAIR-RESULTS.md) · [独立审计](../../reports/fair-v2-final-independent-audit.json) | 四组同开发机会、同业务工具、同总预算；采购用独立穷举验最优。全通过不能分辨模型能力、工具能力与题目难度各自贡献多少。 |
| 需要知识，就必须用 Skill 吗？按需比预加载省吗？ | SQL 两题，Skill 与返回相同资料的普通查询工具均 2/2，无资料组 0/2（询问定义）。另在正式任务中，24 份手册那组按需比全量少 31.5% tokens，3 份那组多 1.7%。[SQL 实际执行](../../fieldwork/2026-11-08/langchain-reference/README.md) · [同题配对资源](../../reports/fair-v2-resource-comparison.json) | 前者比较知识获取方式；后者固定同一批中的正文和题目，仅比较何时读取。不能从不同题目的两批推断普适规模阈值。 |
| 资料传到了，就算交付完整吗？ | 同三道日语电商题各两次：原专家、给退货专家补物流工具、主循环的主要业务结论均正确；按预定标准看最终说明是否完整，分别为 5/6、2/6、6/6。漏掉的日期或政策已传到协调者。[事前判据](../../fieldwork/2026-11-08/haty/prereg.md) · [逐项结果](../../fieldwork/2026-11-08/haty/README.md) | 有证据、得到正确结论、把依据告诉客户，三件事可以分别验。本地严格说明覆盖与上游确定性得分不能混作一个指标。 |

**执行安全另有一类证据。** [商务审批](../../fieldwork/2026-11-08/commerce/README.md)复现了基于旧价的两份草案先后获批，使第二次实际涨价 45%；[安全循环](../../fieldwork/2026-11-08/aidless/README.md)验证了最终文本审查不能撤回此前的写入。它们直接支持在执行时核验状态与回执，不用于单／多 Agent 的优劣排名。

[研究档案](../records/README.md)保留早期基线、装置修正和未完成批次，供追溯上述判断的形成过程。新题现已公开，再次运行是回归。要检验泛化或生产效果，请另设未用于调优的代表性任务。
