# 实验总账：从提出问题到验证边界

研究单位是一次**给定用户目标、场景状态与预算的任务**。同一任务可以用几个模型回合、调多个工具。重复运行不是新题，跨项目的成功定义也不相同。把下面每项读成一个能被反驳的小主张，不要把分子分母相加。

| 阶段／项目 | 怎么设实验 | 观察、失败与可追溯材料 |
|---|---|---|
| S1 · 客服 | 以条件退货为例，四组共享业务工具、身份校验、动作门控和评分。先做开发、记录确认计划，固定版本比较所有组；发现桥接器对批量工具的限制后修复，用已见题做回归。 | V1 四组各 16/16；V2 三个单循环各 16/16、按需加载 13/16。V2 未重跑 multi，所以不能把 V1 multi 与 V2 拼一起。看[规格](../../SPEC.md)、[结果](../../RESULTS.md)、[修正](../records/CORRECTION.md)、[逐次观测](../../data/observations.csv)。 |
| S2 · 困难诊断 | 增加组合采购、条件修订与账务核对。core 只测 tools/eager/skills/domain 四种；另有资料表示及分支核验的计划，不是都实际跑完了。 | 48 次计划中，25 通过、2 个业务结果错误、2 个用尽本任务预算、1 次超时、3 个受共享停止影响、15 个未开始。把金额贴错组合与“专家答对但协调者没提交”分别追到工具契约和预算。[矩阵](../../HARD-MATRIX.md) · [失败报告](../../HARD-RESULTS.md)。 |
| S3 · 有界优化后留出复测 | 四组同样的两轮开发机会、相同建议知识正文（对应知识组）、共同计价与提交工具、主子共享 24 次调用上限。冻结源码、知识、题和验收；6 道采购、3 道修订、3 道账务新题，每组每题重复两次。 | 四组各 24/24，无重试；工具组平均 60,753 tokens，另三组全量 80,099、按需 66,722、可委派 86,744。工具只给模型所提候选报价；独立程序穷举验最优。不是评测者把解藏进工具。[比较规格](../../FAIR-SPEC.md) · [正式结果](../../FAIR-RESULTS.md) · [逐次独立核验](../../reports/fair-v2-final-independent-audit.json) · [配对用量](../../reports/fair-v2-resource-comparison.json)。 |
| U1 · Anthropic 官方 kit | 先跑工程测试和两个 19 题冒烟，再复算作者原有两种迁移；新实验固定工具，只换交接／补证据／折回。另设相同 14 次请求上限，直接跑两套原版应用的 t11。 | 作者折回 22→23/24，邻题也有回退；新三臂全部 6/6，调用 25/25/16。t11 两边都已开单，只有完成版在上限内交付单号。额外写和重复写的反例能骗过部分上游评分。[预登记](../../fieldwork/2026-11-08/kit/PREREG.md) · [过程及逐项结果](../../fieldwork/2026-11-08/kit/README.md)。 |
| U2 · hatyibei 日语电商 | 复算作者 CSV；在原循环上做同三题×两次的 A（原专家）、A1（给退货专家加物流工具）、B（直接查工具、按需读手册）。原始判分与预登记的说明覆盖分开。 | 作者主实验 A 34/36、B 35/36 是旧的含模型裁判结果；本次三组主要结论均正确，严格说明覆盖 5/6、2/6、6/6，调用 42/32/28。缺失说明在专家回传之后仍可见。[协议](../../fieldwork/2026-11-08/haty/prereg.md) · [逐题证据](../../fieldwork/2026-11-08/haty/README.md)。 |
| U3 · Anthropic commerce-agents | 导购与库存草案各一场，分别核 UI、工具状态与批准前后库存；不用模型随机碰错，直接向同一后端依次提交两份旧草案。 | 两个业务流程按预期；基准价 49 时提议 40 和 58，先后批准使第二次实际涨 45%。这是对“相对**当前**价不得超过 20%”这一额外性质的反例，不是生产事故。[项目、执行及负例](../../fieldwork/2026-11-08/commerce/README.md)。 |
| U4 · aidless 安全循环 | 通知条件成立并获批、成立但拒绝、不成立三种状态；原循环有／无手册各重复两次。额外注入“拒写却口头声称成功”“写后 verifier 拒绝”和覆盖率假阳性。 | 两组均 6/6，调用 16/22，各实际发送两次（本地模拟）。门控能拦动作，文本与事务仍须单独核验。[协议](../../fieldwork/2026-11-08/aidless/PROTOCOL.md) · [逐项边界](../../fieldwork/2026-11-08/aidless/README.md)。 |
| K1 · LangChain 教程附项 | 单循环，两个公司 SQL 口径，分别给原版 Skill、普通字典提供相同正文、完全不给。最终 SQL 再换数据执行。 | 2/2、2/2、0/2。无资料时请求澄清是合理行为；这里的“未通过”仅指没有得到正确查询。[教程快照、方法及输出核验](../../fieldwork/2026-11-08/langchain-reference/README.md)。 |

**覆盖边界。** S3 是冻结之后才跑的留出实例；如今题目公开，再跑就是回归。U1/U2 涉及同题架构比较；U3/U4 用来发现业务及执行边界，不能用两者的工程测试通过数佐证架构优势。K1 的两份数据库检验同一条 SQL，会增加语义检验强度，不会增加独立问题的数量。
