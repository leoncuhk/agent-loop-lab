# 新实验预登记：只移动执行者，不同时改业务工具

问题：同样的业务 API 和模型，跨域条件写入必须转给另一段上下文时，自由 brief、补交接、折回主循环对结果和调用数有什么影响？这是基于官方 kit 的新机制实验，不是重跑作者 Claude 轨迹。

- 都运行官方 reference_loop.Agent 与合成 Backend / CustomerBackend。三臂共享订单追踪、退货资格、策略在工具中强制执行的 start_return、营销偏好工具、用户、预算与权限。主循环均可以读；自由交接 A 和补交接 B 各自将写工具交给对应领域的专业子循环，A 仅传模型写的 brief，B 额外附原请求和发起委派决策前主循环已见的权威读回执。C 直接由主循环持有相同写工具；将两条相同的写作业要求交给主循环。全部写入仅发生在该轮新建的内存后端。
- 两对反事实中，同家族给模型的用户文字完全相同，只改后端条件：S=订单 5002 的 ETA 在 10 月 3 日之后则退订单 5001（S+ ETA=10/04；S− ETA=10/03，即临界等号不能写）；E=订单 5001 可退才关闭营销邮件，不要退货（E+ 可退；E− final_sale）。每项均要求返回可机读的条件事实与具体结果。签入同一个 C-1001。
- 主指标：模型正常结束；正确权威条件工具回执进入决策上下文；实际动作列表逐项精确符合要求，禁止重复或多余写；所有写之前主循环已见权威回执（同一批读写不算）；验证最终状态/操作回执；最终状态行正确。另报两条独立读条件、正负例、专家是否实际运行，以及包含传输开销的调用与 token。正负例必须能区分总写/从不写。条件为假时不强制调用专家。
- 一轮 4 个状态 × 3 臂；采用轮换顺序，arm order 按 S+ ABC、E− BCA、S− CAB、E+ CBA。一轮完成后，如果总额度至少还剩 36 次，完整复跑两个正例 × 三臂（S+ BCA，E+ ACB）；否则不开始复跑。单格上限 6 次（主/子共享），全批最多 96 次，最大并行 2。每格从零初始化，不拿失败补跑。额度耗尽原样保留，运输故障单列，不能宣称无差异或计算统计显著性。
- 如果原本没有丢信息，补交接可能不提升质量；高成功率且折入少调用只代表在两个简短、低上下文负载的家族中少了编排成本，不覆盖独立所有权/并行专家/大型日志/生产效果。没有 Claude API 时通过共享 Codex 传输使用同一模型，不使用工具搜索、流式调用、真实业务服务或计价推断。
