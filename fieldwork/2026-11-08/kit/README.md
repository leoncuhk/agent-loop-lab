# 实践一：Anthropic single-agent-loop-kit

这次检验的具体问题是：系统已经知道 ETA 错过截止日，接下来该交给退货专家、给专家补足证据，还是由主循环直接开退货单？单看最终一句“可以退”分不出三者，必须查后台到底有没有开单、什么时候开的。

实验使用 [Anthropic 官方仓库固定版本](https://github.com/anthropics/single-agent-loop-kit/tree/c43796287b83bec847db923f07131d1cc8de750d) 的模拟商店与执行循环，区分四件事：原生工程复跑、作者 Claude 日志复算、我们用同一个真实模型做的小型机制对照、原样应用的单题演示。所有“动作”和“回执”均只存在单次试验的内存后端。

## 原生工具与作者证据

- 原生测试 **48/48**；原版六个专家的路由器和上游完成版单循环各跑了 **19 个离线 smoke、0 个 harness error**。离线模型按规则出招，作者明确不计质量分。
- 上游第一次实跑：12 题 × 2 次，退货折入前后 **22/24 → 23/24**。条件退货 t11 从 0/2 升至 2/2，普通物流 t01 从 2/2 降至 1/2。t11 原始两次均已告诉客户正确 ETA，却没有发起退货；折入后两次后台都有 create_return。原作者这一改还包括主循环获得业务工具、改路由和在写接口内强制资格校验，不能把效果单归因于少了专家；未做完有/无 Skill 对照。
- 上游第二次是**保留诊断专家、改为结构化工具**：17 题 × 2 次 **32/34 → 31/34**；另外补跑的 t01/t10 各四次，双方都是 **8/8**。主路由没有数据接口，不能独立核实专家回传的证据。两次上游试验都使用作者记录的 Claude 模型；后续 19 题、全部迁移后的 single_loop、merge 和 upkeep 不能拿这些数字代证。
- 官方 coupling 对 200 条合成流量统计出 322 次专家调用；coverage 在 12 题基线返回 1，6/200 条出现的 account+returns 没有覆盖；17 题补上该组合，退出码变成 0，但 orders+shipping+returns 只有一直未通过的 t11。**覆盖到组合不等于正确完成交接。** 我们构造同一题两次重复，一次只调 orders、另一次只调 shipping，官方 coverage 仍打印全覆盖并返回 0，原因是它先对同题的多次重复取并集。
- 上游 t11 的判分给正确 ETA 文字、RMA 和一笔所需退货即可。实测重复开同一笔退货、在退货外额外改营销偏好，都仍通过；较严格的 t13 也放过重复的合法写入。[反例脚本](probe.py) 并列检查本次新面板，写后补查、重复写、额外写和凭空给事实均被拒绝；这不表示新判分器覆盖所有可能的错误。

## 我们的新机制对照

[预登记](PREREG.md)固定了 S、E 两种请求，各有条件成立与不成立；同一家族两种世界的用户文字字节相同，模型只能读工具判断。S 看 5002 的 ETA：严格晚于 10 月 3 日才退 5001（10 月 4 日要写，恰好 3 日要保留）；E 看 5001 可退与否：可退才关闭营销邮件，但任何时候都不能开退货。三组共用官方 Agent loop、签入客户、权威读工具、返回资格校验和写操作，只改变谁拿到写工具，以及专家看到的输入。A 由主循环生成自由 brief，B 同样保留专家只额外附原用户请求和主循环已经看到的权威回执，C 由主循环持相同写工具直接执行，保留相同的领域操作要求。这里不评估 Skills、Claude 原生 API 或工具搜索。

每次调用都通过共用 Codex bridge，工具确由官方 kit 在本地执行；主循环不仅要最终读到条件，决定写入之前还必须已经看到结果，同批中先执行读回调再执行写回调不能蒙混过关。另核对完整有序后台动作、执行回执、账户状态和用户要求的状态行。不得重试挑好结果。这里没有人为撕掉 A 组自由摘要；如果它忠实传递了条件，就应该通关。更长的工作流、外部接管、900 行诊断日志、真实用户表达和长期可靠性不在样本内。

| 处理方式 | 首轮四个状态 | 两个正例复跑 | 正例模型调用 / 场 | 反例模型调用 / 场 | 全 6 场调用 | 总输入 / 输出 tokens |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A：自由 brief 保留专家 | 4/4 | 2/2 | 5–6 | 2 | 25 | 165,271 / 1,465 |
| B：同一专家，附原文和已见回执 | 4/4 | 2/2 | 5–6 | 2 | 25 | 166,920 / 1,484 |
| C：折入主循环，工具不变 | 4/4 | 2/2 | 3 | 2 | 16 | 108,183 / 724 |

**查到了同一个结果，差异在谁执行最后一步。** S+ 中 A 的主循环自己把“10 月 4 日晚于 3 日、退的是另一单 5001、原因太小”正确写进了 brief。B 补上原文和真实读回执，没有多挽回失败；C 读到 4 日后调用同一个 start_return，得到同一张 RMA-5001。E+ 均只关闭了营销邮件。每种方式的四个正例都准确写一次，两个反例都没有写；反例中根本不用启动执行专家。两组保留专家的 25 次与折入的 16 次可以在逐步轨迹中解释：正例多了委派和汇总；A 和 B 各有一次额外查询退货资格。以同样的六场计，折入少了 36% 模型调用。输入包含 CLI 固有上下文和缓存部分，不是原生 API 的 token 或美元成本。

只有两种用户表述、四个后端状态，重复只覆盖正例。它给出了“可靠业务工具就位后，保留专家也可能完成”的**可执行反例**，没有估计交接丢失率，也不能把“附回执无额外得分”解释为修接口永远没用。这里不故意制造缺失字段或随机丢包；在自由 brief 本已传到位的样本上看不出恢复收益。账户与退货的 API 已经很薄且能自行查资格，此处少跑上下文划算；如果某专家读长日志、有独立负责人或能并行工作，应换上能检验这些价值的任务，再做是否保留的决定。

## 官方完整应用的 t11 原样演示

[追加预登记](NATIVE-LIVE-PLAN.md)对相同原题、同一模型、相同的每格 14 次调用上限，直接运行两种未经修改的上游应用与原生 run_case；没有跑完整的 19 题真实模型回归。

| 原样程序 | 发生了什么 | 模型调用 | 原生评分 |
| --- | --- | ---: | --- |
| 路由器和专家 app | 先问退货、再查订单、查运输，又回到退货；最后一次模型决定创建退货，未产生给客户的最终答复 | 14，上限耗尽 | 未返回，不能记成“没有开单” |
| 完成版 single_loop | 首轮同批 track_order 和 load_skill，次轮 start_return，末轮答复 ETA 和 RMA-5001 | 3 | 通过，后台恰有一张退货单 |

原生 runner 遇到预算异常不会导出半程动作。[离线回放](replay_native.py)把已保留的模型响应按次送回原样应用，重放中每次待发请求的序列化内容都必须与原请求**逐字节一致**；没有发新模型请求。原版匹配 14/14 次，确实已在模拟后台创建一次退货，但还没有最终回复；完成版匹配 3/3，重现了同一动作和同一最终回答。**业务动作已完成、面向用户的服务未完成，两件事可以同时为真。** 原版若再给额度会不会完成，本次没有测试。

该演示比较的是两套打包实现：完成版同时改了路由、操作程序、按需手册、资格与签入校验、工具粒度。它不能隔离折入本身的因果影响；隔离问题请看上面的三臂对照。新消融 66 次与本例 17 次合计 **83 次真实模型请求**，没有原生 Claude 调用。

## 如何复核或复跑

[机器摘要](summary.json)给出首次四题、正／负例、重复、逐格资源以及上游日志复算数；本批原始证据（本机 `runs/oss-fieldwork-20261108/kit`）留在本机忽略目录，包括 archive、原样运行命令与输出、逐调用请求/回复/用量、事件和动作。不分发这些原始运行材料。源 archive 按固定提交生成；上游 smoke 的 run.json 如果自行发现外层仓库，其 Git 字段不能替代这里的 archive SHA。环境为 Python 3.11.15、Codex CLI 0.167.0、gpt-6.1-sol / low。新面板的实际时延含共享队列，不用作原生 API 性能或计价依据。

在 agent-loop-lab 根目录，指定一个未使用过的运行目录；前两行 Python 命令只做离线检查。后面两个运行命令调用真实模型，共用已有的登录态，不读取或搬运密钥。最后两条只重放／重算、检查并写输出：

~~~bash
kit=fieldwork/2026-11-08/kit
run=runs/my-kit-fieldwork
python3 -B "$kit/native.py" "$run"
python3 -B "$kit/probe.py" "$run"
python3 -B "$kit/panel.py" "$run"
python3 -B "$kit/native_live.py" "$run"
python3 -B "$kit/replay_native.py" "$run"   # 若 native_live 因额度不足跳过，则也跳过本条
python3 -B "$kit/summarize.py" "$run" --summary "$run/summary.json"
~~~

已有本机原始批次时只需最后一条，将 run 改为 runs/oss-fieldwork-20261108/kit。机器摘要与逐格结果、调用次数、原始 token 回执、模型真正收到的交接文字、写事件和上游结果文件相互核对；模型和工具环境改变后，重新运行的选择可能不同。
