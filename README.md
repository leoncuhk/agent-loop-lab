# Agent Loop Lab：什么时候值得拆出子 Agent？

**如果一项任务要先查清事实，再依照用户的条件采取行动，优先让一个主 Agent 带着业务工具做完。** 在我们的短任务对照中，单 Agent 和专家协作都能办对；单 Agent 的优势是少了交接，完成同一批任务用的模型调用更少。业务知识仍可以由不同团队维护，按需给做决定的 Agent 读取。

这是对 [Anthropic 关于把子 Agent 折回主循环的建议](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)的独立检验。以下结果来自同一型号的真实模型（`gpt-6.1-sol`）与合成业务系统，不是生产成功率。

## 一个能区分做法的实验

用户有两笔订单：“查 5002 的预计到货日，**只有晚于 10 月 3 日，才退 5001**。”我们给模型完全相同的请求，只改物流系统里的事实：预计 **10 月 4 日**到就该退；**10 月 3 日**到就不能退。这样，总是开单、总是不办，或答得正确却没办事，都不能过关。

我们在 Anthropic 的迁移 kit 上固定模型、查询工具和业务后端，比较由谁执行最后一步。除了上述退货题，还有一类“符合条件才更改账户偏好”的任务。两类各有一个应写和一个不应写的状态，再各重复一次应写状态，所以**每种做法是 6 次运行，不是 6 道独立新题**。

| 谁执行最后一步 | 通过任务 | 六次运行合计模型调用 |
|---|---:|---:|
| 主 Agent 查完直接执行 | 6/6 | **16** |
| 主 Agent 写说明，交给领域专家执行 | 6/6 | 25 |
| 交给同一专家，同时附上原请求和查询回执 | 6/6 | 25 |

判分同时看三件事：决定写入前是否已经看到了条件事实，后台是否**恰好**执行了获准动作，最终是否向用户交代了正确结果。这组对照支持的是**同样办对，少 9 次模型调用**；没有测出成功率差异，也没有把调用次数换算成费用或耗时。[事前协议](fieldwork/2026-11-08/kit/PREREG.md) · [逐组结果](fieldwork/2026-11-08/kit/README.md)

## 其他实验给这个结论加了什么条件？

| 要判断什么 | 怎么比较、怎么判 | 观察到的结果 |
|---|---|---|
| **任务更复杂时，不加手册也能做对吗？** | 冻结后取 12 道新题：6 道组合采购、3 道需求修订、3 道账务审计。每题每组跑两遍，共享工具和预算。独立程序穷举采购最优解、核对账务事件和实际提交。 | 工具单循环、全量加载手册、按需加载手册、允许委派，**各 24/24 首次通过**。工具组平均 tokens 最少；允许委派组只在 6/24 次中真用了子 Agent。这批题能比较用量，分不出正确率冠军。[正式结果](FAIR-RESULTS.md) |
| **需要业务知识，就必须用 Skill 吗？** | 针对“活跃客户”和“库存补货”两个公司口径，让同一主 Agent 读 Skill、用普通查询工具读相同正文，或拿不到资料。把生成的 SQL 放到两份数据上实际执行。 | 有资料的两组均答对 2/2；没资料时两次都追问定义。这里需要的是公司规则，Skill 是提供它的一种方式。[SQL 对照](fieldwork/2026-11-08/langchain-reference/README.md) |
| **按需读手册能省多少？** | 在正式对照中，让同一主 Agent 全量或按需读取相同正文；在每个手册规模内，用相同题目比较用量和通过数。 | 通过数相同。24 份手册的子集，按需平均少用 31.5% tokens；3 份手册的另一批题，按需反而多用 1.7%。两批题不同，不能据此定通用阈值。[配对用量](reports/fair-v2-resource-comparison.json) |
| **给专家补工具，能解决交接问题吗？** | 在日语电商的同一道退货题上，各跑两遍：原专家分工、给退货专家补物流查询、主 Agent 直接查。分别核对查到的事实、协调者收到的内容和客户看到的答复。 | 补工具把原来的 10、14 次调用降为 6、6 次；专家两次都传回“9/28 签收、10/28 截止”，客户却只看到截止日。主 Agent 两次各用 5 次调用，均给出两个日期。若只要求告知截止日，两种答案都对；若承诺解释依据，交付质量就不同。[逐题记录](fieldwork/2026-11-08/haty/README.md) |

**把结论用到自己的业务：** 先写清楚用户希望办成什么、决定前必须知道什么、办完后拿什么作证。缺公司规则，就补资料；涉及退款或改价，让工具在写入时核对权限与当前状态。若几条调查可以独立并行，或确实需要隔离权限、独立核验，再考虑子 Agent。以相同总预算比较经核实的新增发现、端到端耗时或检错率。**本仓尚未证明子 Agent 在这些独立任务上的净收益。** [选型方法与验收模板](docs/method.md)

[商务审批](fieldwork/2026-11-08/commerce/README.md)与[安全循环](fieldwork/2026-11-08/aidless/README.md)另测了执行边界：两份基于旧价格的草案先后获批，实际涨幅可超限；写入后即使拦住最终答复，也不能撤销动作。这两项检验解释为什么要查后台状态，不用于架构排名。
